# 公众号文章素材：Article Studio —— AI 文章创作与配图工作台

> 用途：本文档是公众号文章的**结构化素材包**，不是成稿。所有功能描述均来自仓库 README / PRD，可核实；标注「⚠️ 需补充」的地方由作者本人提供，生成文章时不得虚构。
>
> 开源仓库：**https://github.com/taoyuan97/article-studio**

---

## 1. 产品速览

- **一句话定位**：Article Studio 是一个本地单机运行的 AI 文章创作与配图工作台——对话式生成/修订长文、AI 配图沉淀素材库、一键推送到公众号草稿箱，写作到发布一条链路全在一个工具里完成。
- **开源地址**：https://github.com/taoyuan97/article-studio
- **运行形态**：单仓双工程，本地单机运行，SQLite 存储，**数据不出本机**。
- **目标读者**：公众号创作者、自媒体人、技术博主——尤其是已经在用 AI 辅助写作、但被「写作 → 配图 → 排版 → 发布」割裂流程折腾的人。

## 2. 痛点切入（成稿时的引子素材）

现在的 AI 写作工具不少，但完整的创作链路是断的：

- 在聊天工具里生成文章，改稿靠复制粘贴来回倒腾，旧版本很快找不到；
- 配图要另开绘图工具，提示词随手记、用完就丢，图片散落在各个目录；
- 排版发布又是一套：找图、传图、调样式，最后再到公众号后台手动操作；
- 数据放在别人的云端，长文素材和账号凭据都得交出去。

Article Studio 的思路：把「写、改、配图、发布」收进一个本地工作台，每一步的产物（版本、素材、发布记录）都自动沉淀、可回看。

## 3. 核心卖点（每个都附功能事实支撑）

### 卖点一：对话式长文创作，每次修改自动落版本

- 左侧对话、右侧正文的工作台形态，发送「写一篇关于 X 的文章」即 SSE 流式生成；
- 继续对话提出修改要求，产出 v2、v3……**每次生成落一个只读历史版本**，版本下拉可随时回看任意历史版本；
- 标题自动生成；生成中可「停止」（不落版本）；失败可原消息重试；
- 双模型切换（DeepSeek / Moonshot），顶部一键切换。

### 卖点二：配图工作台双模式——既能直接生图，也能一键编排全文配图方案

- **行动模式（默认）**：输入画面描述 → 选档位/比例 → 发送，进度条实时推进；完成后可保存为素材；失败展示脱敏详情卡片；
- **计划模式**：选定文章与版本后「一键编排」，LLM 按字数/章节结构/情绪基调自动产出整套配图提示词方案——每张图含插入位置（块级锚点，与发布插图编号一致）、横版/方图/竖版排版建议、统一风格提示词，每条提示词可一键复制到任意 AI 绘图工具；方案自动入库；
- 生图模型支持通义万相 / 即梦；生成的图可存入**素材库**，详情页可回链来源配图会话。

### 卖点三：三步向导，一键推送到公众号草稿箱

- 步骤一「版本和信息」：选文章/版本，弹窗单选封面（从全部图片中选），填作者；
- 步骤二「配图与位置」：在正文画布上点击任意段落/标题设置插入点，弹窗多选图片（本文配图置顶 + 素材库图片），按勾选顺序插入；已插图内联展示、hover 可删除；
- 步骤三「选主题」：左侧选主题卡，右侧手机框即时渲染主题预览，**所见即最终发布效果**；预览可切编辑模式原位修改 Markdown；
- 确认后推送至**公众号草稿箱**——只建草稿、不群发，最终发布权仍在自己手里；
- 发布记录按时间倒序可查（成功/失败、media_id），失败可展开错误码；「查看快照」可回看发布时的完整内容与配图。

### 卖点四：本地单机、数据不出本机

- 单进程部署，SQLite 持久化，全部数据在 `backend/data/`（业务库 `article.sqlite3` + 图片 `assets/`）；
- 删除对应数据目录即重置，没有账号体系，没有云端同步；
- 不想消耗真实 API 额度：后端可换假模型服务器（`uv run python scripts/dev_fake_server.py`），API/SSE/持久化行为与真实后端完全一致；
- 没有公众号也能体验发布流程：`PUBLISH_FAKE_MODE=true` 走假发布，返回 `FAKE_MEDIA_xxx`，全流程（含失败重试）可演练。

### 卖点五（工程向，可选）：拿来即跑的开发体验

- Windows 双击 `scripts/start-all.cmd` 一键起前后端，`stop-all.cmd` 一键停；
- 生产形态单进程：FastAPI 直接托管前端构建产物，一条 `uvicorn` 命令起完整应用；
- 测试覆盖：后端 pytest 82 例、前端 Vitest 62 例、Playwright E2E 13 例（假模型，无需真实 Key）。

## 4. 典型工作流（从一句话到公众号草稿）

1. 仪表盘点「新建文章」（或文章列表进入），左侧对话框输入写作需求；
2. 流式生成全文 Markdown → 继续对话迭代 → 版本栏随时回看 v1…vn；
3. 需要离线存档：导出任意正式版本为 Markdown 或 TXT，系统「另存为」保存到指定位置；
4. 切到配图工作台：「计划模式」一键生成全文配图方案，或「行动模式」逐张生图，满意的保存进素材库；
5. 文章工作台右上「发布到公众号」：选版本/封面/作者 → 画布锚点插图 → 选主题看真机预览（可编辑）→ 确认推送草稿箱；
6. 到公众号后台检查草稿、手动群发；发布记录里随时回看结果与内容快照。

## 5. 技术架构（技术读者向素材）

- **前端**：React 19 + Vite + TypeScript + AntD 5，8 个路由（仪表盘 / 文章列表 / 文章工作台 / 配图工作台 / 素材库 / 发布向导 / 发布记录 / 快照详情）；
- **后端**：FastAPI 单进程应用（API + SSE + SQLite），`article_agent/` 是 LangGraph 智能体——意图路由（追问/生成/全文修改/无关引导）、上下文预算压缩（窗口 80%）、失败脱敏；
- **发布线**：经 wenyan-mcp（`@wenyan-md/mcp`）渲染排版并对接公众号接口；
- **部署**：开发态前后端分离热更新（Vite proxy 转发 `/api`），生产态 `SERVE_FRONTEND=true` 单进程同源托管；
- 详细设计见仓库 `docs/tech/tech-design.md`、`docs/prd/prd.md`。

## 6. 快速上手（成稿可精简为「三步跑起来」）

环境：Windows 10+、Node.js 20.19+、Python 3.11+、uv（pnpm 经 corepack，无需全局安装）。

```powershell
# 1. 配置 Key（文章线至少一个：DeepSeek / Moonshot；配图、发布可选）
copy backend\.env.example backend\.env   # 然后编辑填写

# 2. 双击 scripts\start-all.cmd（首次自动装依赖）
# 后端 http://127.0.0.1:8000（API 文档 /docs），前端 http://localhost:5173

# 3. 浏览器打开 http://localhost:5173 开始使用；完毕双击 scripts\stop-all.cmd
```

没有 Key 想先体验：`cd backend; uv run python scripts/dev_fake_server.py` 起假模型服务器。

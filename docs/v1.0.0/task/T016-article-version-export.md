# T016：文章工作台版本导出（Markdown / TXT）

## 1. 任务信息

- 状态：已完成（2026-08-27）
- 优先级：P1
- 类型：功能新增（前端）
- 前置任务：T003（文章工作台与版本查看）
- 后续任务：无
- 目标目录：`frontend/`、`docs/`
- 创建日期：2026-08-27
- 关联文档：`docs/prd/prd.md`（文章工作台）、`docs/tech/tech-design.md`（前端路由与文章版本接口）
- 需求来源：用户提出——文章工作台增加“导出”入口，支持选择文章版本并以 Markdown 或纯文本保存到电脑指定路径

## 2. 需求与现状

| 项             | 现状                                             | 调整后                                                               |
| -------------- | ------------------------------------------------ | -------------------------------------------------------------------- |
| 工作台顶部操作 | 仅有状态标识和“发布到公众号”入口                 | 在“发布到公众号”左侧增加“导出”按钮                                   |
| 文章版本       | 正文区可查看当前版本或历史版本；历史正文按需请求 | 导出弹窗列出全部正式版本，默认选中工作台当前展示的版本               |
| 本地文件导出   | 无                                               | 支持原始 Markdown（`.md`）和去除 Markdown 语法后的纯文本（`.txt`）   |
| 保存位置       | 无                                               | Chrome / Edge 使用系统“另存为”窗口选择路径；不支持时退化为浏览器下载 |
| 生成中正文     | 页面会展示尚未持久化的流式临时正文               | 允许打开导出，但只导出最近一次已完成的正式版本，不导出临时正文       |

现有 `GET /api/articles/{article_id}/workspace` 已返回版本摘要列表和当前版本完整正文；`GET /api/articles/{article_id}/versions/{version_id}` 可取得任意历史版本完整正文。因此本任务无需新增或修改后端接口。

## 3. 已确认决策点（2026-08-27 与用户对齐）

| #   | 决策                   | 结论                                                                           |
| --- | ---------------------- | ------------------------------------------------------------------------------ |
| ①   | TXT 内容               | 转换为纯文本，去掉标题、列表、链接等 Markdown 语法标记，保留可读文本和合理换行 |
| ②   | Markdown 内容          | 原样导出所选版本的 `content_markdown`，不添加 frontmatter、版本号或其他元数据  |
| ③   | 默认格式               | Markdown（`.md`）                                                              |
| ④   | 默认文件名             | `文章标题-v版本号.扩展名`；用户可在系统保存窗口修改                            |
| ⑤   | 不支持路径选择的浏览器 | 自动退化为普通下载，并提示文件已保存到浏览器下载目录                           |
| ⑥   | 生成过程中导出         | 允许；只导出正式版本，不导出流式临时内容                                       |
| ⑦   | 无正式版本             | 禁用“导出”按钮，并提示“请先生成文章内容”                                       |

## 4. 范围

### 4.1 工作台入口与状态

调整 `frontend/src/pages/ArticleWorkspacePage.tsx`：

- 顶部右侧新增操作容器，顺序固定为“导出”“发布到公众号”；保留现有运行状态标识。
- “导出”按钮仅在 workspace 已加载且至少存在一个正式版本时可用。
- workspace 加载中或无正式版本时禁用按钮；无版本时通过 antd `Tooltip` 提示“请先生成文章内容”。
- 点击“导出”打开弹窗；不跳转路由，不改变正文区当前查看版本。
- 每次打开弹窗时重新计算默认版本：
  1. 正在查看历史版本：选中该历史版本；
  2. 正在查看当前版本：选中 `current_version.id`；
  3. 正在生成临时正文：仍选中最近一次已完成的 `current_version.id`。
- 新版本生成并成为当前版本后，沿用工作台现有“返回当前版本”行为；下次打开弹窗默认选择新版本。

### 4.2 导出弹窗

新增 `frontend/src/features/article-export/ExportArticleModal.tsx`：

- 标题：“导出文章”。
- 版本选择：antd `Select`，选项按 workspace 现有版本顺序展示，文案为 `v{version_number} · {title}`。
- 格式选择：antd `Radio.Group` 或 `Segmented`，包含：
  - Markdown 文档（`.md`）；
  - TXT 文本（`.txt`）。
- 每次打开默认格式重置为 Markdown（决策 ③）。
- 辅助提示：“点击导出后，可在系统窗口中选择保存位置和文件名。”
- 底部操作：“取消”“导出”；读取历史版本或写文件期间“导出”按钮显示 loading，并避免重复提交。
- 关闭弹窗不改变工作台正文版本；再次打开时不保留上一次的版本和格式选择。

建议组件接收版本摘要、当前展示版本 ID，以及一个按版本 ID 解析完整正文的回调，使 UI 与数据获取、文件写入逻辑保持清晰边界。

### 4.3 版本正文解析

在 `ArticleWorkspacePage` 或专用 hook 中按以下优先级取得所选正式版本正文：

1. 所选 ID 等于 `current_version.id`：直接使用 workspace 中的 `current_version`；
2. 所选 ID 等于已加载的 `selectedVersion.id`：复用正在查看的历史版本详情；
3. 其他历史版本：通过 TanStack Query `queryClient.fetchQuery` 调用现有 `articlesApi.getVersion(articleId, versionId)`，复用 `['version', articleId, versionId]` 缓存键。

约束：

- 不使用 `runState.temporaryArticle`，保证决策 ⑥“只导出正式版本”。
- 版本读取失败时保留弹窗和用户选择，显示后端错误信息，可再次点击重试。
- 导出过程中 workspace 若产生新版本，本次操作仍按用户已选择的版本 ID 完成，不静默切换导出对象。

### 4.4 Markdown 转纯文本

新增 `frontend/src/features/article-export/markdownToPlainText.ts`，基于 Markdown AST 做结构化转换，避免仅用正则导致嵌套列表、链接、代码块等内容损坏。若引入解析包，须作为前端直接依赖声明，不依赖包管理器偶然提升的传递依赖。

转换规则：

| Markdown 结构           | TXT 输出                                                               |
| ----------------------- | ---------------------------------------------------------------------- |
| ATX / Setext 标题       | 去掉标题标记，保留标题文字并独占一行                                   |
| 段落、软换行、硬换行    | 保留文字；段落之间保留一个空行                                         |
| 无序/有序列表、任务列表 | 去掉项目符号、序号及任务框语法；每个列表项独占一行，嵌套项保留内容顺序 |
| 粗体、斜体、删除线      | 去掉格式标记，保留内部文字                                             |
| 链接                    | 保留链接文字，去掉链接地址和 Markdown 语法                             |
| 图片                    | 保留非空 alt 文本；无 alt 时不输出内容                                 |
| 行内代码                | 去掉反引号，保留代码内容                                               |
| 围栏/缩进代码块         | 去掉围栏，原样保留代码内容和内部换行                                   |
| 引用                    | 去掉 `>` 标记，保留引用文字                                            |
| 分隔线                  | 不输出                                                                 |
| 转义字符、HTML 实体     | 输出对应可读字符                                                       |
| Markdown 内嵌 HTML      | 去掉标签，保留其中可读文本；不得执行 HTML 或脚本                       |

输出收尾规则：

- 统一内部换行为 `\n`；移除行尾多余空白；连续空行压缩为最多一个空行。
- 去掉文件开头和结尾的空白行，文件末尾统一保留一个换行。
- Markdown 导出不经过以上转换，必须保持 `content_markdown` 字符串原样（决策 ②），包括其原始换行和末尾状态。

### 4.5 文件名与本地保存

新增 `frontend/src/features/article-export/exportFile.ts`，集中处理文件名、MIME 类型和浏览器能力降级。

**默认文件名**

- 模板：`{版本标题}-v{version_number}.{extension}`；这里的“文章标题”取所选版本的 `title`，确保历史版本改过标题时文件名与导出内容对应。
- 清理 Windows 非法字符 `< > : " / \\ | ? *` 和控制字符，合并多余空白，去掉结尾的句点/空格。
- 标题清理后为空时退化为 `文章-v{version_number}.{extension}`。
- 为避免系统路径限制，对标题主体设置合理长度上限，同时保留版本号和扩展名。

**格式映射**

| 格式     | 扩展名 | MIME 类型                     | 内容                    |
| -------- | ------ | ----------------------------- | ----------------------- |
| Markdown | `.md`  | `text/markdown;charset=utf-8` | 原始 `content_markdown` |
| TXT      | `.txt` | `text/plain;charset=utf-8`    | Markdown 转换后的纯文本 |

**保存策略**

1. 能力检测到 `window.showSaveFilePicker` 时：
   - 必须在“导出”点击处理链中先调用文件选择器、取得文件句柄，再按需读取历史版本正文，避免网络等待导致浏览器临时用户激活失效；
   - 传入 `suggestedName` 和与格式匹配的 `types`；
   - 打开系统“另存为”窗口，由用户选择目录并可修改文件名；
   - 创建 writable、写入 UTF-8 文本并关闭；
   - 成功后提示“文章已导出”。
2. API 不存在时：
   - 使用 `Blob`、`URL.createObjectURL` 和临时 `<a download>` 触发普通下载；
   - 及时移除临时节点并 `URL.revokeObjectURL`；
   - 提示“当前浏览器不支持选择保存路径，文件已保存到浏览器下载目录”。
3. 用户在系统窗口取消时（`AbortError`）：静默结束，不显示成功或失败提示，也不退化为普通下载。
4. 读取正文、创建文件或写入失败时：显示“导出失败：{可读错误}”，不得错误提示已保存。

File System Access API 仅用于本地浏览器写入，不向后端发送本地路径。需要为尚未包含在 TypeScript DOM 声明中的 API 添加最小范围类型声明，避免使用全局 `any`。

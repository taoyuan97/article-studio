## 1. 假模型端到端联调（无需真实 key，推荐先用）

T003/T004 的联调验证均基于假模型服务器完成，不消耗任何真实 API 额度。
脚本：`backend/scripts/dev_fake_server.py`（通过 `create_app` 依赖注入假 LLM 与假生图 provider，其余 API/SSE/SQLite 行为与真实后端完全一致）。

```powershell
# 终端 1：假模型后端（默认 8000 端口，数据写入 backend/data/dev-fake）
cd backend
uv run python scripts/dev_fake_server.py

# 终端 2：前端开发服务器（/api 与 /static 代理到 127.0.0.1:8000）
cd frontend
pnpm dev    # http://localhost:5173
```

可调参数（测试取消等需要更长的运行窗口时）：

```powershell
uv run python scripts/dev_fake_server.py --chunk-delay 1.0 --image-delay 25
# chunk-delay：文章流式每个 chunk 的间隔秒数（默认 0.03）
# image-delay：生图耗时秒数（默认 1.5）
# --data-dir 可指定独立数据目录；--port 可换端口（需同步改 vite.config.ts 代理目标）
```

假模型行为约定（联调时按此构造场景）：

| 场景 | 触发方式 | 预期 |
| --- | --- | --- |
| 生成文章 | 新文章第 1 条消息 | 流式生成「冒烟测试文章 v1」并提交版本 |
| 修订文章 | 同一文章后续消息 | 生成下一版本（v2、v3…），版本面板可回看 |
| 文章失败卡片 | 消息文本包含「触发失败」 | 延迟 0.5s 后运行失败，红色失败卡片 + 脱敏详情 + 重新发送 |
| 生图成功 | 普通 prompt | 约 N 秒纯色 PNG（N=image-delay），可保存素材 |
| 生图失败卡片 | prompt 包含「触发失败」 | 延迟 0.5s 后生成失败卡片 + 脱敏详情 |

> 勘误（2026-08-24，T006）：失败触发词由「失败」改为「触发失败」——正文模板与上下文压缩摘要中含「失败」二字，短触发词会误触发失败。详见 `manual-tasks-t005-t006.md` §2.2。

验证过的假模型端到端路径（2026-08-23）：

- 文章线：列表/空态/搜索过滤、新建、流式生成 v1、修订 v2、历史版本切换与返回、失败卡片、模型下拉（deepseek/moonshot）、404 错误页、运行中取消（临时内容清空、用户消息保留、无版本提交）。
- 图片线：素材库空态、新建配图、参数浮层（档位/比例切换并持久化回显）、进度条、完成预览、保存素材入库、素材详情弹窗（含来源会话跳转）、失败卡片、运行中取消（无图片无资产）。
- 浏览器 console 全程无红色错误。

数据清理：假模型数据独立存放于 `backend/data/dev-fake/`，随时可整目录删除重置，不影响 `backend/data/` 真实数据。

## 2. 真实模型人工验收（需要真实 key，建议截图留档）

自动化已覆盖假模型路径与后端契约（pytest 51 passed）；以下需要人工用真实 provider 复验。

### 2.1 文章线（对应 T003 验收「MVP 场景 A–G 复验」）

前置：`backend/.env` 配置 DeepSeek 或 Moonshot（已配置，见 `manual-setup.md` §5）。

```powershell
cd backend
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000
# 另一终端
cd frontend
pnpm dev
```

按 MVP 场景逐项复验并记录：

| 场景 | 操作 | 关注点 |
| --- | --- | --- |
| A 新文章与标题 | 新建文章 → 发送「直接写一篇…」 | 生成后文章标题自动更新；列表同步 |
| B 列表过滤 | 列表页输入标题关键词 | 忽略大小写、空关键词恢复全部 |
| C 历史对话继续 | 退出重进同一文章继续追问 | 完整历史保留、同一 thread 继续 |
| D 重启恢复 | 生成中刷新页面 / 重启后端 | 重进显示运行中（可停止/等待）或最终状态 |
| E 取消 | 生成中点「停止」 | 临时内容消失、用户指令保留、无版本 |
| F 失败与重试 | 构造失败（如断网/无效 key）后重试 | 失败卡片脱敏详情；重试不复制用户消息 |
| G 上下文压缩 | 长对话多轮 | （后端断言预算不变量，后端测试已覆盖；人工确认对话不丢上下文即可） |

### 2.2 图片线（对应 T004 验收）

前置：`.env` 中通义万相或即梦 key（已配置并冒烟通过）。

| 验收项 | 操作 | 关注点 |
| --- | --- | --- |
| 真实生成端到端 | 素材库 → 新建配图 → prompt（选档位/比例）→ 生成 → 保存素材 | 进度→完成→预览→入库；素材库可见 |
| 参数随指令提交 | 切换 1K/2K、16:9 等组合 | 实际图片尺寸与所选档位/比例一致；重进会话参数回显 |
| provider 切换 | 下拉切换通义万相/即梦 | 运行中禁用；生成结果元数据与所选 provider 一致 |
| 取消 | 生成中点「停止」 | 无图片资产产生 |
| 失败路径 | 临时改错 key 触发失败 | 失败卡片 + 脱敏详情（不泄露 key） |

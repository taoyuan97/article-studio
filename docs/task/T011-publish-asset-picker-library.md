- 问题来源：人工验收反馈——发布向导第 2 步「配图与位置」无法选择任何配图

## 2. 问题与根因

**现象**：任何文章进入发布向导第 2 步，候选配图恒为空，提示「该文章还没有已保存的配图素材」。

**根因**（已用真实数据核实）：[PublishPage.tsx:80-91](file:///c:/projects/studio/article-studio/frontend/src/pages/PublishPage.tsx#L80-L91) 的过滤条件为：

```
候选配图 = 素材库图片 ∩ (来源会话.article_id === 当前文章)
```

而实际使用中配图会话多从素材库「新建配图」入口独立创建（`article_id` 为空，本地 6 个会话全部如此），素材分属这些会话 → 过滤后候选集恒空。属交互设计与真实使用习惯不匹配，非数据损坏。

**可行性已实证**：后端发布接口按 `asset_id` 解析文件路径，与来源会话无关（ISSUE-001 排障期间以非关联素材发布成功）。**本任务纯前端改动，无后端变更。**

## 3. 目标

第 2 步缩略图墙分组展示：

- **本文配图（N）**：当前文章关联会话下的素材，置顶（仅非空时显示该组）。
- **素材库图片（N）**：其余全部图片素材。

任一组中的图片均可勾选、设封面、参与位置编排，交互与现有逻辑完全一致。

## 4. 范围

### 4.1 必须实现

**PublishPage.tsx**

- 保留现有 `articleAssets` 计算逻辑。
- 新增全量素材分组：`articleAssets`（本文配图）+ 其余素材（素材库图片），合并后作为 `availableAssets` 传入编辑器（勾选/位置/封面的既有逻辑不变）。
- 同时传两组数据给编辑器用于分组渲染。

**ImagePlacementEditor.tsx**

- Props 调整：`availableAssets` 改为 `articleAssets: Asset[]` + `libraryAssets: Asset[]`（或等价结构）。
- 缩略图墙分组渲染：
  - 「本文配图（N）」组：仅 `articleAssets.length > 0` 时渲染，标题带计数。
  - 「素材库图片（N）」组：渲染其余素材，标题带计数。
  - 两组共用同一勾选/选中态逻辑（同一 `selectedSet`）。
- 空态文案修正：仅当两组均为空（素材库完全无图片素材）时显示 Empty 引导；「本文配图」为空不再是空态条件。

**global.css**

- 分组标题样式（复用 `publish-step-heading` 或新增轻量分组标题类）。

  - 无关联素材时，不渲染「本文配图」组，仅渲染「素材库图片」组。
